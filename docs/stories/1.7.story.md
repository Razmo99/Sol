### Story

**As a Developer,** I want to migrate the existing `New-CompanyUser` function to use the proven function-based orchestration framework, **so that** the core user creation functionality demonstrates the extensibility pattern while maintaining full backward compatibility and leveraging workflow orchestration capabilities.

### Acceptance Criteria

1. **Workflow Function Extraction**: The existing `New-CompanyUser` logic is extracted into properly attributed workflow functions (`Connect-ToMicrosoftGraph`, `New-CompanyADUser`, `Set-CompanyUserLicenses`, etc.) that integrate with the orchestration framework.

2. **Public Function Migration**: The public `New-CompanyUser` function is updated to use the orchestration framework internally while maintaining identical external behavior, parameters, and return values.

3. **Framework Integration**: The migration demonstrates full integration with the framework's static validation, context management, and workflow execution capabilities.

4. **Backward Compatibility**: All existing parameters, behavior, error handling, and output patterns are preserved exactly, ensuring no breaking changes for current users.

5. **Microsoft Graph Preservation**: All Microsoft Graph API calls, authentication patterns, and error handling from the migrated function are preserved in the new workflow functions.

6. **Testing Validation**: All existing Pester tests continue to pass without modification, and new tests validate the workflow orchestration functionality.

7. **Extensibility Demonstration**: The implementation proves the framework's extensibility by showing how additional user lifecycle operations can be easily added as new workflow functions.

#### Microsoft Graph Integration Patterns
- **Connection**: Uses `Connect-MgGraph` with scopes `User.ReadWrite.All`, `Directory.Read.All`, `Organization.Read.All`
- **User Operations**: `Get-MgUser -UserId $UPN`, `Update-MgUser -UserId $UPN -UsageLocation $Country`
- **License Management**: `Get-MgSubscribedSku`, `Set-MgUserLicense -UserId $UPN -AddLicenses $addLicenses -RemoveLicenses @()`
- **Error Handling**: Comprehensive try-catch blocks with logging module integration

#### Workflow Function Design Principles
- **Single Responsibility**: Each workflow function should handle one logical operation (connect, create user, assign licenses)
- **Clear Contracts**: All functions must have explicit `[ProducesOutput]` declarations matching their return hashtables
- **Parameter Mapping**: Function parameters should align with framework context keys for automatic mapping
- **Error Propagation**: Maintain existing error handling patterns while working within workflow execution context
- **Independent Operation**: Functions should work both standalone and within workflow context

#### Framework Integration Requirements
- **Context Structure**: Design workflow context to include all parameters needed by constituent functions
- **Static Validation**: Ensure framework can validate all dependencies before execution
- **Output Merging**: Verify function outputs are properly merged back to context for downstream functions
- **WhatIf Support**: Maintain existing WhatIf functionality through framework's explicit propagation
- **Logging Integration**: Preserve established logging patterns within workflow execution

#### Backward Compatibility Constraints
- **Parameter Interface**: No changes to New-CompanyUser's public parameter interface
- **Return Values**: Maintain existing return value structure and content
- **Error Messages**: Preserve existing error message patterns and exception types
- **Help Documentation**: Keep existing comment-based help and examples
- **Behavior**: Identical functional behavior under all usage scenarios

#### Testing Strategy
- **Regression Prevention**: All existing tests must pass unchanged to prove backward compatibility
- **Mock Continuity**: Maintain existing Microsoft Graph cmdlet mocking strategies for workflow functions
- **Framework Validation**: New tests should validate framework integration without changing external behavior
- **Scenario Coverage**: Test normal operation, error conditions, WhatIf scenarios, and edge cases
- **Performance**: Ensure workflow orchestration doesn't significantly impact execution performance

#### Extensibility Demonstration
- **Additional Functions**: Create at least one additional workflow function to prove extensibility
- **Workflow Composition**: Show how different workflows can be composed from same function library
- **Epic 2 Preparation**: Validate framework readiness for user offboarding, modification, and other lifecycle operations
- **Documentation**: Clear examples of how to extend the framework with new operations
